### @mavogel — team owner (product-owner agent, prompts, permissions)

**1. Pre-approve the `engineer` subagent for product-owner**

The current `product-owner.json` config already pre-approves `customer`, `qa`, and `ux-designer` in the `subagent` permission rule, so that specific failure looks fixed since this session ran.
- **But:** `engineer` is listed in `availableAgents` yet missing from both `trustedAgents` and the `subagent` permission match. The product-owner's prompt explicitly tells it to "ask the engineer agent whether it is feasible and how big it is," so the first design-review consultation will hit the same cancelled-prompt wall.
- **Change:** Add `"engineer"` to the `trustedAgents` array and to the `subagent` permission match array.
- **Where:** `teams/product-team/agents/product-owner/agent.json.tmpl`

**2. Stop auto-retrying cancelled subagent prompts**

- **What I saw:** After the first customer call was cancelled (the result even says "the user did not reject it"), the agent immediately retried the identical call, which was cancelled again, before finally surfacing the problem to the user.
- **Change:** Add a line to the product-owner prompt: if a subagent permission prompt is cancelled rather than rejected, don't retry it automatically; tell the user the call needs approval and wait.
