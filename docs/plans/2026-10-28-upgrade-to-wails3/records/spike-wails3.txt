GOTCHA A: the scaffold is its own module, so the tool must be pinned in the APP's go.mod:
  $ cd spike && go tool wails3 task darwin:package:universal   -> go: no such tool "wails3"

GOTCHA B: Taskfile cmds call bare `wails3 ...` (generate bindings/icons, tool prepare-macos-output, ...).
  `go tool wails3 task` does NOT put itself on PATH (internal/commands/task.go has no PATH handling):
  task: [darwin:common:generate:bindings] wails3 generate bindings -f '...' -clean=true -time-type=Date
  "wails3": executable file not found in $PATH   ERROR exit status 127
  Fix used: go build -o <dir>/wails3 github.com/wailsapp/wails/v3/cmd/wails3 (resolves the go.mod pin)
  and PATH=<dir>:$PATH. (`go install` of the pinned tool into a repo-local GOBIN would work the same.)

======================================================================
DID NOT WORK / CAVEATS
======================================================================
- `go tool wails3 task ...` fails unless a `wails3` binary is on PATH (Taskfiles shell out to `wails3`).
- Tool pin must be in the app module's go.mod (scaffold is a separate module "changeme").
- Scaffold vite config requires generated bindings; dropped for the no-bindings approach.
- WindowRuntimeReady never fires for a page that doesn't load the Wails JS runtime -> SMOKE run hangs.
- `task` CLI var overrides of CGO_CFLAGS are ignored; only process env overrides work.
- Not tested: dev mode, DMG, Windows/Linux builds, clicking menus.
