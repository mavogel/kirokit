What this shows

Purpose
The kirokit desktop app this task builds, drawn from the approved sidebar-layout mockup. Only three things change: a first-launch screen that clones the repository, Settings with the repository address and Update, and how button commands reach the terminal.
Drawn from
The approved sidebar-layout page (tokens, layout, pages, dialogs, shortcuts, unchanged). Teams, agents, skills and MCP versions from this repository; the newest release tag is v0.2.0.
Simulated
Nothing is cloned, installed or stored. In the clone address or the Settings address: "missing" makes git fail, "private" makes git ask you to sign in in the kirokit tab, and "notag" clones a repository with no release yet. "Check again" always finds the key. The real app reads install state from kirokit's install records and shows each record's time.
Your call
A: buttons type their command into your own shell, as the mockup did. B: buttons run in a kirokit tab, and your shell keeps its own tab. Switch below to compare.

Settings

Where kirokit installs agents, and where its templates come from.

Where Kiro reads its agents. Defaults to ~/.kiro unless KIRO_HOME is set in your shell. A team installed in the old folder stays there; uninstall it first to remove it.
Saving a different address clones it into a fresh folder. Your installed team stays installed until you install from the new templates.

Your own shell, started in kirokit's copy of the repository. Typed kirokit commands update the screens too.

Replace the installed team?

Only one team is installed at a time. Replacing runs kirokit uninstall for the installed team, then kirokit install for the new one.
